# QMS Assistant KKB

Локальное приложение для статистики инцидентов и подготовки стандартов учреждения (СТУ) по шаблону ККБ. Python 3.12+, FastAPI, SQLite, SQLAlchemy, Pydantic, Jinja, JavaScript. Используйте синтетические данные без сведений о пациентах.

Текущие разделы: Главная, Инциденты, Конструктор СТУ, Внутренние аудиты (заглушка), Отчётность, Настройки. Чат, база знаний, общий модуль документов и отдельный реестр рисков удалены из рабочего интерфейса и HTTP API. Таблица оценки рисков внутри СТУ сохранена. ИИ-провайдеры в рабочем приложении не создаются и не вызываются. Старые документы, переписка и оригинальные файлы остаются в хранилище для сохранности; публичных страниц доступа к ним нет.

## Windows 10: запуск

Откройте PowerShell в папке проекта. Требуется установленный Python 3.12+ 64-bit.

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000 и оставьте PowerShell открытым. Остановка — Ctrl+C. Для следующего запуска достаточно последней команды. Активация окружения и изменение ExecutionPolicy не нужны. Если порт занят, задайте `--port 8001` и откройте соответствующий адрес.

Linux:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Интернет нужен для первой установки зависимостей. Само приложение и экспорт работают локально. Word/LibreOffice на сервере не требуются.

## Обновление существующей копии

1. Остановите сервер и скопируйте **весь каталог `data`** в отдельное место.
2. Скачайте свежий ZIP ветки main из GitHub. Замените папки `app`, `tests`, `docs`, README.md и `.env.example`. **Сохраните свои `data`, `.env`, `.venv`.** Важно скопировать `app/assets/stu_base.docx` вместе с остальным `app`.
3. Новых зависимостей относительно предыдущей версии нет. При обновлении с ранних этапов выполните установку из requirements.txt.
4. Запустите сервер прежней командой и нажмите Ctrl+F5.

Текущая схема SQLite — **v6**, добавлена таблица черновиков СТУ. Перед миграцией создаётся проверенная копия SQLite `data/backups/qms-before-v6-*.sqlite3`; ошибки откатывают миграцию. Старые данные не удаляются. После обновления не запускайте старую версию приложения с этой базой. Автоматическая копия SQLite не включает оригиналы файлов и не заменяет копию всего `data`.

## Конструктор СТУ

Откройте **Конструктор СТУ → Создать СТУ**. Разделы формы раскрываются отдельно. Незавершённый документ можно сохранить; экспорт требует заполнить поля из списка ошибок. Кнопка «Сохранить и скачать DOCX» сначала сохраняет черновик, затем формирует Word. Номер стандарта вводится вручную по реестру, без автоматического присвоения.

- **Реквизиты:** номер СТУ, название, редакция, необязательные номер/дата приказа и дата введения. Даты приказа и введения необязательны; кнопка «Очистить дату» удаляет значение. В Word незаполненные даты остаются пустыми. Редакция — число 1–999.
- **Согласование:** добавляемые строки «Согласовал / Разработал», должность и фамилия с инициалами. Подпись и дата в Word пустые.
- **Аннотация и разделы 1–3:** ручной текст, сохраняются абзацы и переносы строк. Назначение, область применения, нормативные ссылки.
- **4 Сокращения и обозначения:** отдельно добавляемые строки сокращений с расшифровками и терминов с определениями. В Word сначала сокращения в алфавитном порядке, затем отдельно отсортированные термины. Формат «название - значение», название термина жирное. Старые строки вида «СТУ — стандарт учреждения» переносятся в новую структуру при открытии; непарсируемый или слишком длинный старый текст сохраняется отдельным полем. Заполнение новых строк обязательно для экспорта; черновик можно сохранить частично.
- **Ответственность:** отдельное поле ответственного и согласованный текст. Матрица позволяет добавлять, переименовывать, удалять и переставлять должности/подразделения, отмечать отдельные ячейки или всю строку. В Word отметки становятся V. Удаление запрашивает подтверждение. Можно ввести общую строку «Все структурные подразделения».
- **Широкая матрица:** вручную включите «Альбомная страница». Матрица получает отдельную альбомную страницу, дальнейшие страницы снова книжные. Максимум 20 должностей и 100 подразделений; большое число столбцов ухудшает читаемость. При необходимости сократите названия или состав таблицы. Ограничение пяти участников к этой матрице не применяется.
- **Описание процесса:** ввод названия для шаблонной фразы либо полностью собственный текст. Для каждого добавленного процесса создаются подпункт 6.1, 6.2… на отдельной странице, страница «Квалиграмма» и страница «Текстовое описание к квалиграмме». Первая буква названия каждого процесса при экспорте становится заглавной; остальной регистр сохраняется, название также обновляется в содержании. Кнопка «Открыть квалиграмму» сохраняет СТУ и открывает редактор схемы. Без сохранённой схемы обе страницы остаются пустыми.
- **Оценка рисков:** возможный прецедент и два значения 1–5; ранг — произведение, повторно вычисляемое сервером. Поле ранга вручную не задаётся. Сохраняется объединённая шапка «Риски».
- **Показатели процесса:** десять вводимых полей и автоматический порядковый номер. В Word сохраняются 11 столбцов и объединения «Внесение данных» / «Проведение анализа данных для управления процессом».
- **Внесение изменений:** отдельно получатель предложений и ответственный за изменение подлинника. Текст хранения и сетевых ресурсов включается по согласованному образцу.
- **Приложения:** добавляемые названия, отдельная страница «Приложение N» с местом для заполнения в Word.
- **Первая редакция:** лист регистрации изменений не выводится. Для редакций 2 и выше обязательны строки изменений, страницы, вид и описание, а также отметка проверки. Номер изменения присваивается по порядку строк; ячейка редакции объединяется.
- **Ведомость обучения:** заключительный блок с пустыми полями и 48-строчной таблицей скопирован из шаблона.

Титул с логотипом и ведомость обучения взяты из предоставленного шаблона. В последней строке титульной таблицы — «Красноярск, текущий год» (Arial 12, по центру); год определяется при экспорте по времени Красноярска. Верхний колонтитул: номер/название слева Arial 12, страница X из Y и редакция справа Arial 9, цвет #808080; границы таблицы чёрные. Для титула отдельный колонтитул. Текстовые разделы и таблицы оформлены на основе образца, нумерация соответствует согласованным 10 разделам.

Уточнённое оформление DOCX: основной текст и содержание Arial 12, первая строка обычного абзаца и заголовков разделов — 1 см. «СОДЕРЖАНИЕ» и заголовки приложений центрированы без отступов. Титул сохраняет своё оформление. Лист согласования Arial 10, без заливки, столбцы 3,5 / 5,44 / 3,25 / 2,5 / 2,5 см. В третьем заголовке «инициалы» с новой строки; строки данных высотой не менее 1 см с расширением для длинного текста. Матрица Arial 10. Страница названия процесса: Arial 24, обычный шрифт, невидимые границы, средняя ячейка #F2F2F2. Оценка рисков Arial 12: данные названия риска по левому краю, остальные ячейки по центру. Показатели процесса — Arial 10; ширины всех 11 столбцов взяты из исходного шаблона. Пустые абзацы, возникавшие при объединении шапок матрицы ответственности, рисков и показателей, удаляются. В перечисленных таблицах установлено вертикальное центрирование; согласование, матрица и показатели также центрированы горизонтально. Приложение — один жирный заголовок «ПРИЛОЖЕНИЕ N», затем название через мягкий перенос Shift+Enter, с заглавной первой буквой и сохранением остального регистра. Ведомость обучения сохраняет исходную сетку, высоты строк и отступы, шрифт явно задан Arial 12.

Язык проверки всего DOCX — русский (ru-RU), включая основной текст, таблицы, колонтитулы и стили. Явные отметки «не проверять правописание» из шаблона удаляются.

Содержание формируется из структуры документа и содержит поле TOC. Стили Word TOC1/TOC2 заданы Arial 12 без дубликатов идентификаторов, чтобы обновление содержания сохраняло шрифт. **После открытия и ручного дополнения обновите поля в Word: Ctrl+A, F9, затем обновление содержания целиком.** При необходимости обновите поле содержания отдельно через контекстное меню. Номера страниц заранее не выдумываются. Разные редакторы Word/LibreOffice могут по-разному переносить строки — перед утверждением проверьте итоговый DOCX на своём компьютере.

Сохранение ручное. При уходе с несохранёнными изменениями браузер предупреждает. Две вкладки защищены от перезаписи: устаревшее сохранение даёт сообщение о конфликте. Скопируйте несохранённый текст отдельно, затем обновите вкладку. Кнопка «Создать копию» копирует **последний сохранённый** черновик. Номер и редакция копии меняются пользователем. История каждого сохранения и восстановление старой версии пока не реализованы; для отдельной редакции используйте копию черновика.

Ограничения: поля до 500 символов, большие текстовые разделы до 20 000, до 100 сокращений и 100 терминов (название до 500, значение до 5000 символов); до 50 согласующих, 20 процессов, 100 рисков, 50 показателей, 30 приложений и 100 изменений. Это конструктор новых документов; загрузка произвольного старого DOC и автоматическое преобразование его в заполненную форму не реализованы. Клинические действия не генерируются: пользователь вводит содержание схемы самостоятельно. Оригинал утверждённого СТУ с подписями в репозитории отсутствует.

## Конструктор квалиграмм

В СТУ раскройте «6 ОПИСАНИЕ ПРОЦЕССА», добавьте процесс и нажмите «Открыть квалиграмму». Схема привязана к постоянному идентификатору процесса: переименование и перестановка процессов её не теряют. Копирование СТУ копирует сохранённые схемы. Возвращайтесь по ссылке «Вернуться к СТУ», чтобы получить актуальную версию черновика.

1. Создайте до пяти дорожек с названиями должностей/исполнителей.
2. Добавляйте действия, начало/окончание, зелёный вход подразделения, красный выход ветви, серое внешнее подразделение без отдельной дорожки, И/ИЛИ, документ, пояснение, дату и номер. Перемещайте блоки мышью, меняйте координаты, ширину, высоту, шрифт и подпись в свойствах. «Подогнать высоту» помогает вместить текст.
3. Для действия выберите исполнителей и одного ответственного. «Растянуть по дорожкам исполнителей» разместит общий блок; при нескольких исполнителях над ним появляются «Отв.» и «Уч.».
4. «Соединить два блока»: нажмите исходный, затем конечный блок. Выберите стрелку в списке связей, задайте подпись, точки присоединения и тип: чёрная информационная, красная пунктирная для брака или красная для высокого риска. Повторное нажатие кнопки отменяет режим соединения. Стрелки прямые; обход препятствий и ручные точки изгиба пока не реализованы.
5. «Составить из шагов» создаёт редактируемое описание из введённых действий и связей, без ИИ. При замене существующего текста запрашивается подтверждение. Порядок описания — сверху вниз, затем слева направо; номер шага можно задать вручную.
6. Нажмите «Сохранить схему». PNG и VDX также сначала сохраняют черновик. Ошибки текста/исполнителей и выхода за лист блокируют экспорт; отсутствие входа/выхода и несвязанные блоки показаны как предупреждения.
7. В DOCX схема вставляется как PNG на отдельную страницу выбранной ориентации; далее идёт введённое текстовое описание. Редактировать отдельные фигуры внутри Word нельзя — измените схему на сайте и экспортируйте снова. Приложения заполняются в Word.

**Visio 2007:** скачайте VDX (Visio 2003 XML), откройте его через «Файл → Открыть», при необходимости выбрав тип XML/VDX, затем сохраните как VSD. Экспорт содержит фигуры, редактируемые подписи, группы и связи с точками присоединения, а не растровую картинку. Проверено чтение через LibreOffice/libvisio; непосредственно Visio 2007 в облачной среде отсутствует, окончательная проверка открытия и поведения соединителей нужна на рабочем ПК. Импорт VSD/VDX обратно на сайт и двустороннее сохранение правок Visio не реализованы. Второй случайный лист исходного образца не используется.

Если старая версия VDX не открывается с ошибкой XML `Char / Color / DblUnderline`, обновите `app/qualigram_vdx.py`, перезапустите сервер и скачайте VDX заново. В экспорте исправлены последовательности полей Visio 2003; сохранённую на сайте схему пересоздавать не требуется. Проверка секций в тестах дополняет проверку чтения через LibreOffice и не заменяет проверку непосредственно в Visio 2007.

Одна схема — один лист A4, книжный или альбомный, до 100 блоков и 200 связей. Масштаб при вставке в Word уменьшается до размера страницы: для плотных схем проверяйте читаемость. «Убрать схему из СТУ» удаляет её после подтверждения и возвращает пустые страницы. Истории/отмены правок схем пока нет; для сохранения варианта сделайте копию СТУ. Все данные хранятся в существующем SQLite, внешние запросы не выполняются, новые зависимости не нужны.

Последние правки DOCX: верхний колонтитул 12,94 / 4,5 см, видимые боковые границы объединённых ячеек матрицы и показателей, расширенный столбец вероятности, один пробел в заголовке ведомости и жирное «Обучение прошел, со стандартом ознакомлен:».

## Инциденты и отчёты

1. Загрузите XLSX в «Инцидентах», проверьте столбцы и предпросмотр, затем подтвердите импорт.
2. В согласованном образце номер — B «Номер инцидента»; A «№» не участвует. Период — C «Дата инцидента», отделение госпитализации — N. Дата регистрации — F; E содержит месяцы. Можно сопоставить иной файл вручную.
3. Основной режим — уникальные номера с объединением одинаковых выбранных данных. Конфликтующие дубликаты блокируются. Режим всех строк выбирается явно. Именные/медицинские идентифицирующие поля не входят в аналитические записи; исходный файл хранится целиком локально.
4. Фильтруйте даты, несколько отделений, группы, события, важность, статус, корневую причину; можно исключить статусы. Полные названия отделений сохраняются, сокращения ГХО, ОАР 2, ТО 1, НРС служат поисковыми подсказками.
5. Графики, PNG, Парето, кварталы, повторяемость, сравнение периодов, перекрёстные таблицы и полный экспорт Excel используют одинаковую выборку. Рисунки ограничены первыми 15 отделениями / 24 месяцами / 12 группами; ограничения подписаны. Нажатие элемента со ссылкой открывает записи. Нулевой знаменатель не подменяется 0% изменения.
6. «Сравнить две выгрузки» сопоставляет два подтверждённых набора по точному номеру: новые, отсутствующие, изменённые, без изменений. Отсутствие номера не означает удаление. Наборы не объединяются.
7. «Отчёт за месяц или квартал» сохраняет категории и заменяет даты календарным периодом; предыдущий период подставляется автоматически. Доступны DOCX с диаграммами и комментарием и полный XLSX. Комментарий отчёта не хранится на сервере.

Ранее предложенная новая карта «Группа событий × месяц» пока не добавлена: пользователь остановил эту работу для обсуждения. Существующие графики сохраняются.

Лимиты импорта: по умолчанию 10 МиБ, до 20 листов, 20 000 строк, 100 столбцов, 1 млн ячеек, 32 МиБ распакованных данных. Формулы, макросы и XML-сущности не исполняются; формулы в выбранных полях дают ошибку строки. Чтение ограничено тайм-аутом 30 секунд; в Linux также память/CPU. Наборы хранятся отдельно, повторное подтверждение не дублирует записи.

Все показатели — программные частоты записей. Полнота периода, клинические причины и тяжесть не определяются автоматически. Для частот на госпитализации/койко-дни нужны соответствующие знаменатели.

## Данные и конфигурация

`.env` необязателен; основные параметры:

```dotenv
QMS_DATA_DIR=data
QMS_MAX_UPLOAD_MB=10
```

Прежние QMS_AI_* и QMS_CLOUD_* могут оставаться в приватном `.env`, но текущий запуск `app.main:app` не создаёт ИИ-сервис и не использует ключи. Не включайте `.env` в Git.

Данные: `data/qms.sqlite3`, `data/incident_imports`, `data/uploads` (исторические файлы), `data/logs`, `data/backups`. Для резервной копии остановите сервер и скопируйте **весь data**. Черновики СТУ находятся в SQLite, готовые DOCX — в загрузках браузера. Архив экспортов на сервере не ведётся.

Однопользовательское приложение без авторизации: слушайте только 127.0.0.1, не публикуйте сервер в сети. Docker, PostgreSQL, Qdrant и тяжёлые модели не используются.
