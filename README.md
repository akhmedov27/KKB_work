# QMS Assistant KKB

Локальное рабочее пространство менеджера системы менеджмента качества. Реализованы этапы **QMS-001–QMS-005** по ТЗ версии 1.0. Используйте только синтетические тестовые данные. Это прототип, а не готовая медицинская или экспертная система.

## Запуск на Windows 10

Требуется Python 3.12+ (64-bit), установленный с опцией **Add python.exe to PATH**. Откройте PowerShell в папке проекта и выполняйте команды по одной:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000** в браузере. PowerShell оставьте открытым. Остановить сервер: Ctrl+C. Если порт занят, используйте `--port 8001` и соответствующий адрес. Активировать окружение и менять ExecutionPolicy не нужно. Команды запускаются из корня проекта. Используйте один процесс сервера: один файл обрабатывается за раз.

Файл `.env` необязателен: настройки по умолчанию работают без него. При необходимости скопируйте `.env.example` в `.env`, не заменяя существующую конфигурацию. Если команда `python` не показывает номер версии, сначала исправьте установку Python или PATH; не продолжайте следующие команды.

Linux:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

При первой установке зависимостей нужен интернет. Для работы чата и обработки файлов интернет не требуется: JavaScript, CSS и HTMX хранятся в проекте.

## Обновление существующей копии на Windows

1. Остановите сервер: Ctrl+C.
2. Сделайте полную резервную копию папки `data` в отдельное место.
3. Скачайте свежий ZIP ветки main из GitHub. Перенесите `app`, `tests`, `README.md`, `requirements.txt` в вашу рабочую папку с заменой файлов. **Сохраните свои `data`, `.env`, `.venv`.**
4. При обновлении с QMS-003 или более раннего этапа установите зависимости QMS-004 (для перехода QMS-004 → QMS-005 новых зависимостей нет):

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

5. Запустите прежнюю команду Uvicorn и нажмите Ctrl+F5 в браузере. Не запускайте старую и новую версии одновременно с одной базой.

Схема SQLite обновляется автоматически при старте. Перед изменением существующей базы создаётся проверенная резервная копия SQLite в `data/backups`. Если копию создать или проверить нельзя, обновление не продолжается. Повторный запуск не дублирует миграцию.

## Что работает

- Русскоязычный интерфейс, восемь разделов навигации, мобильное меню с закрытием Escape, обозначение текущего раздела и навигация с клавиатуры.
- Светлая/тёмная темы. Выбор хранится в браузере; при запрете localStorage тема действует до перехода на другую страницу.
- MockProvider с явно обозначенными тестовыми ответами. Реальный ИИ не подключён.
- Отдельные диалоги с названиями до 120 символов. Пара запрос/ответ и время активности сохраняются одной транзакцией; ошибка записи не оставляет половину пары. На странице до 50 сообщений, более ранние доступны по ссылке. Список диалогов — по 20 записей. Главная без параметров открывает последний активный диалог, URL с `conversation_id` сохраняет выбор.
- Загрузка непустых DOCX/XLSX/PDF до 10 МиБ по умолчанию. Оригиналы получают случайные внутренние имена и сохраняются локально; путь исходного имени не используется. Размер, название и дата сохраняются в SQLite. Каталог оригиналов не публикуется веб-сервером.
- Локальное извлечение и сохранение текста, просмотр результата и ошибок, повторная обработка старых документов.
- База знаний: поиск по названию, номеру и тексту, фильтры, ручная классификация и реквизиты, ссылки на источники и напоминание о пересмотре.
- Журнал операций и ошибок с ротацией, без текста запросов и документов, исходных имён файлов, секретов или необработанных исключений парсеров.

## QMS-004: загрузка и обработка документов

В «Базе знаний» загрузите тестовый документ. Дождитесь результата и нажмите **«Открыть документ»**. В списке можно открыть ранее загруженный файл и нажать **«Извлечь текст»**. Повторная обработка заменяет сохранённый результат для этого файла. Она не создаёт новую копию оригинала и не меняет его дату загрузки.

Поддерживается:

| Формат | Извлекается | Ограничения полноты |
| --- | --- | --- |
| DOCX | Основной текст и текст ячеек таблиц верхнего уровня, в порядке блоков | Без колонтитулов, текстовых полей, вложенных таблиц, OCR изображений, исходного оформления и определения страниц |
| XLSX | Значения ячеек с названиями листов и номерами строк | Формулы не вычисляются: видны только сохранённые в файле результаты. Макросы, диаграммы и внешние источники не запускаются |
| PDF | Доступный текстовый слой с номерами страниц | Без OCR. Порядок чтения сложных колонок и полнота текста зависят от структуры PDF |

Статусы: **«Не обработан»**, **«Текст извлечён»**, **«Нет доступного текста»**, **«Ошибка обработки»**. PDF-скан без текста не выдаётся за успешно распознанный документ. Смешанный PDF может иметь страницы без текста — об этом выводится предупреждение. Проверяйте результат по оригиналу.

Если файл повреждён, имеет неверное внутреннее содержимое, защищён паролем или превышает лимиты обработки, оригинал и его метаданные остаются в хранилище, а статус объясняет ошибку. Извлечённый текст не подставляется в чат и не передаётся ИИ. Само извлечение не является анализом; локальный поиск по результатам доступен в QMS-005.

### Ограничения ресурсов и обработка

- Один процесс разбора за раз на процесс сервера; при занятости новый файл сохраняется как «Не обработан», обработку можно повторить кнопкой.
- Разбор запускается отдельным процессом с тайм-аутом 20 секунд; по истечении времени процесс завершается. Это не полноценная изолированная песочница.
- Не более 500 000 символов текста; превышение возвращает ошибку вместо молчаливого усечения.
- Office: не более 2000 ZIP-элементов и 32 МиБ распакованных данных; также проверяется чрезмерная степень сжатия. Архивы не распаковываются на диск. XML с DTD и сущностями отвергается. Пакеты с двоичными вложениями или макросами не поддерживаются.
- XLSX: до 20 листов, 50 000 строк на лист и 100 000 просмотренных ячеек суммарно (включая пустые ячейки в диапазоне).
- PDF: до 200 страниц. Документы с паролем не поддерживаются.
- В Linux процесс разбора дополнительно ограничен 512 МиБ виртуальной памяти и 20 секундами CPU. В Windows жёсткого лимита памяти в этой реализации нет: применяются тайм-аут и ограничения объёма/обхода документа.

Парсеры не открывают документы в Word/Excel, не выполняют содержимое, формулы или макросы и не переходят по ссылкам. Антивирусная проверка не реализована. Проверка формата не гарантирует безопасность любого файла; используйте тестовые документы из известных источников.

## QMS-005: база знаний и поиск

Откройте «База знаний». Введите слово или фразу и нажмите **«Найти»**. Поиск выполняется локально по имени файла, наименованию, номеру документа и успешно извлечённому тексту. Он не вызывает ИИ, не выполняет внешних запросов и не требует отдельного сервиса или индексации.

### Как устроен поиск

- Ищется буквальное вхождение введённой фразы без учёта регистра, в том числе русского. Символы `%`, `_` и кавычки не являются шаблонами или командами.
- Нет морфологии, ранжирования, исправления опечаток и смыслового поиска. `ё` и `е` различаются; пробелы и переносы строк внутри фразы значимы. Если длинная фраза не находится в PDF, попробуйте отдельное слово.
- Фильтры статуса, типа документа и подразделения применяются совместно с запросом. Подразделение ищется по части названия без учёта регистра. Кнопка сброса возвращает полный список.
- По умолчанию видны все статусы, включая неуказанный, архивный и отменённый. Статус документа и статус обработки — разные поля. Результат поиска не подтверждает, что документ действующий.
- Результаты показываются по 20 документов, новые загрузки — первыми. Есть общее количество и переход между страницами с сохранением фильтров. Ограничения списка в 100 файлов больше нет.
- В результатах выводится первый подходящий фрагмент текста. Совпадение только в имени/номере обозначается отдельно. Ошибочные и пустые результаты извлечения не участвуют в поиске по содержимому, но файл можно найти по названию.

Поиск использует параметризованные запросы SQLite с Unicode `casefold`. Просматриваются сохранённые тексты, без загрузки всего корпуса в память приложения; в результаты передаются только короткие фрагменты. Это простой поиск для небольшого локального реестра: для большого корпуса время поиска растёт с объёмом текстов. Полнотекстовый индекс и смысловой поиск пока не реализованы.

### Карточка документа и классификация

Откройте документ по названию. В «Реквизитах документа» можно вручную сохранить:

- наименование (до 255 символов), номер, версию/редакцию;
- тип: СТУ, ОАР, положение, инструкция, регламент, процедура, документ аудита, отчёт, другое или не указан;
- статус: не указан, действующий, архивный, отменённый;
- подразделение, дату утверждения и дату пересмотра.

Пустое наименование означает отображение исходного имени файла. Даты необязательны, некорректные значения отклоняются без изменения прежних реквизитов. Дата загрузки и исходное имя сохраняются независимо от введённых реквизитов. Тип и статус не угадываются автоматически. В новой и старой карточке они по умолчанию **«Не указан»**.

У действующего документа с датой пересмотра раньше текущего локального дня появляется напоминание **«Срок пересмотра истёк»**. Оно не отменяет документ и не подтверждает несоответствие. Система пока не связывает файлы в цепочки редакций и не определяет автоматически последнюю действующую версию. Изменение реквизитов заменяет текущие значения; истории их изменений пока нет. При работе в нескольких вкладках сохраняется последнее отправленное состояние карточки.

### Ссылки на источники

Новые и повторные извлечения сохраняют координаты: основной текст DOCX, номер страницы PDF, название листа XLSX. Из результата поиска можно перейти прямо к соответствующему фрагменту на странице документа. Номера разделов DOCX и номера страниц Word не определяются и не придумываются. Номер, версия и статус документа берутся из ручных реквизитов.

Для текстов, извлечённых до QMS-005, координат нет: поиск работает и ведёт к полному тексту, но страница/лист не указываются. Нажмите **«Повторить извлечение»**, чтобы получить координаты. Они записываются парсером отдельно от текста: имитация строки «Страница 999» внутри документа не становится координатой источника.

Это выдача фрагментов и ссылок на источники, **не ответы ИИ**. Интеграция ИИ относится к QMS-006 и пока не подключена. Исходный документ остаётся основанием для проверки полноты текста и актуальности редакции.

### Самостоятельная проверка этапа

Загрузите тестовый документ, откройте карточку, заполните название, номер, тип и статус. Сохраните и обновите страницу. Найдите его по части названия, номеру и слову из текста в другом регистре. Проверьте фильтры действующих/архивных документов и ссылку источника. Повторите извлечение старого PDF/XLSX и проверьте переход к странице/листу. Перезапустите сервер: реквизиты, тексты и история чатов должны остаться.

## Конфигурация и данные

| Переменная | Назначение |
| --- | --- |
| `QMS_DATA_DIR` | Каталог данных; по умолчанию `data` относительно рабочей папки |
| `QMS_MAX_UPLOAD_MB` | Лимит загрузки 1–100 МиБ, по умолчанию 10. Увеличение не отменяет лимиты обработки |
| `QMS_AI_PROVIDER` | `mock`, `local`, `cloud`. Работает только `mock`, другие возвращают 503 с объяснением |
| `QMS_LOCAL_MODEL`, `QMS_CLOUD_MODEL`, `QMS_CLOUD_ENDPOINT` | Зарезервированы; внешние ИИ-запросы и чтение API-ключей не реализованы |

Основные данные: `data/qms.sqlite3`, `data/uploads/`, `data/logs/app.log`, `data/backups/`. SQLite хранит диалоги, сообщения, реквизиты и результаты извлечения с координатами источников. Связи между записями защищены внешними ключами. Время показано в UTC. В Git не включаются `.env`, `.venv`, `data`, логи и кеши.

### Совместимость и миграции

Схема версии 0 (QMS-001/QMS-002) обновляется с переносом сообщений в «История до QMS-003», с сохранением идентификаторов, ролей, текста, дат и метаданных документов. Схема версии 1 (QMS-003) обновляется добавлением таблицы результатов извлечения. Схема версии 2 (QMS-004) получает таблицу ручных реквизитов и поле координат источников для извлечённого текста. Текущая версия — **`PRAGMA user_version=3`**. Перед миграцией создаётся `data/backups/qms-before-v3-<дата>-<идентификатор>.sqlite3`. Старые резервные копии не удаляются. Миграция транзакционная; ошибка откатывает изменения схемы. Более новая или неизвестная старая схема останавливает запуск.

Старые оригиналы автоматически не обрабатываются: откройте документ и нажмите кнопку извлечения. Старые успешно извлечённые тексты доступны для поиска сразу; координаты страницы/листа появятся после повторной обработки. Статус и тип старых документов по умолчанию «Не указан». Переписка, названия диалогов и оригинальные файлы не изменяются. После обновления базы не запускайте с ней старую версию приложения.

### Резервное копирование

Остановите сервер и скопируйте **весь каталог `data`** в защищённое локальное место. Для восстановления при остановленном сервере верните каталог целиком. Не копируйте рабочую SQLite отдельно во время записи.

Автоматическая копия перед миграцией включает только SQLite, **без оригиналов файлов**; она не заменяет полную резервную копию. Периодическое резервное копирование не реализовано. Для возврата к старой версии используйте старую полную копию `data` и соответствующую версию кода; записи, сделанные после копии, в ней отсутствуют.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Linux: `.venv/bin/python -m pytest -q`. Тесты создают собственные временные базы и синтетические документы. Результаты описаны в `tests/RESULTS.md`.

Самостоятельно: создайте два диалога, отправьте разные запросы, обновите страницу и перезапустите сервер. Затем загрузите тестовые DOCX с текстом и таблицей, XLSX со значениями, PDF с текстовым слоем. Откройте каждый файл, проверьте текст и повторное извлечение. Загрузите повреждённый PDF и PDF без текстового слоя — убедитесь, что ошибки и отсутствие текста обозначены явно. Не используйте сведения о пациентах.

Необязательная браузерная проверка для разработчика: установите отдельно `playwright==1.62.0`, затем `python -m playwright install chromium`. Запустите сервер на порту 8002 с отдельным каталогом синтетических данных и выполните `python tests/browser_smoke.py`. `QMS_TEST_URL` меняет адрес сервера, `QMS_CHROMIUM_PATH` задаёт путь установленного Chromium. Скрипт сохраняет тестовые диалоги и файл — не направляйте его на рабочие данные. Для обычного использования приложения Playwright не нужен.

## Границы этапа

QMS-006 и последующие этапы не начаты. Пока нет смыслового поиска, RAG, автоматической классификации, генерации Word/Excel, анализа инцидентов, расчёта рисков, аудитов и отчётности. Нет реального ИИ, удаления/переименования диалогов, экспорта истории, контроля версий документов и редактирования серверных настроек в браузере. Функциональные модули обозначены как заглушки. Лента операций в интерфейсе не реализована; операции записываются в журнал.

Это однопользовательский прототип без авторизации. Слушайте только `127.0.0.1`, не публикуйте в сети. Корпоративное внедрение требует согласования ИТ и ИБ. Docker, PostgreSQL, Qdrant и тяжёлые модели не используются. Работа QMS-001–QMS-004 на Windows подтверждена пользователем. QMS-005 проверен в Linux; непосредственная проверка новой базы знаний на Windows ещё требуется.
