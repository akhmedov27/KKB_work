# QMS Assistant KKB

Персональное локальное рабочее пространство менеджера СМК. Реализованы **QMS-001 и QMS-002** по ТЗ версии 1.0 и согласованному перечню базовых функций. Это каркас, а не готовая медицинская или экспертная система. Используйте только синтетические тестовые данные.

## Запуск на Windows 10

Установите Python 3.12 или новее (с python.org, с компонентом Python Launcher). Откройте PowerShell в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`Copy-Item` выполняйте только при отсутствии своего `.env`. Активировать окружение и менять ExecutionPolicy не требуется. Откройте **http://127.0.0.1:8000** в браузере. Остановить сервер: Ctrl+C. Если порт занят, используйте `--port 8001` и соответствующий адрес. Запускайте команды из корня проекта. Один процесс сервера достаточен для указанного оборудования.

Linux / облачная среда:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Откройте все пункты меню. Отправьте синтетический запрос в чат, обновите страницу и перезапустите сервер: история сохранится. В «Базе знаний» загрузите тестовый DOCX, XLSX или PDF. После загрузки обновите список по предложенной ссылке. Для проверки отказа загрузите TXT или файл больше лимита. `/health` проверяет доступность SQLite. В Linux: `.venv/bin/python -m pytest -q`.

## Что работает

- Восемь страниц навигации; русскоязычный адаптивный интерфейс, светлая/тёмная темы.
- Единый тестовый чат с явно обозначенным MockProvider. Пары запрос/ответ сохраняются в одной транзакции SQLite. На странице показываются последние 100 сообщений; остальная история остаётся в БД.
- Локальная загрузка DOCX/XLSX/PDF, лимит по умолчанию 10 МиБ, отклонение пустых файлов. Потоковая запись с удалением частичного файла при отказе. Исходное имя, размер, дата и внутреннее имя сохраняются в SQLite. Внутреннее имя — случайный UUID, каталог загрузок не публикуется веб-сервером.
- Журнал операций и ошибок с ротацией; без текста запросов, содержимого файлов и секретов.
- Конфигурация через `.env` или переменные окружения. JavaScript, CSS и HTMX доступны локально, CDN при запуске не используется.

## Структура

```text
app/
  main.py          # маршруты FastAPI, обработка ошибок, сборка приложения
  config.py        # Pydantic Settings
  models.py        # SQLAlchemy: сообщения и метаданные файлов
  providers.py     # AIProvider, MockProvider, недоступные Local/Cloud
  storage.py       # безопасное именование, лимит и запись загрузок
  templates/       # базовый макет, главная, страницы модулей, сообщения
  static/          # CSS, JS, локальный HTMX 2.0.4 и его MIT-лицензия
tests/test_app.py
requirements.txt
.env.example
.gitignore
```

## Конфигурация и данные

`QMS_DATA_DIR` — каталог данных (по умолчанию `data`, относительно текущей рабочей папки). `QMS_MAX_UPLOAD_MB` — целое число 1–100, размер в МиБ. `QMS_AI_PROVIDER` — `mock`, `local` или `cloud`. Только `mock` работает; другие значения провайдера возвращают 503 с объяснением, не подменяются тестовым ответом. Поля `QMS_LOCAL_MODEL`, `QMS_CLOUD_MODEL`, `QMS_CLOUD_ENDPOINT` зарезервированы: сетевые клиенты и чтение API-ключей не реализованы. Внешних ИИ-запросов нет при любой конфигурации.

Создаются `data/qms.sqlite3`, `data/uploads/`, `data/logs/app.log`. `.env`, данные и окружение исключены из Git. Файлы не извлекаются, не открываются сервером и не исполняются. Проверка расширения **не подтверждает формат и безопасность содержимого**, антивирус и парсеры не реализованы.

Резервная копия: остановите сервер и скопируйте **весь** каталог `data` в защищённое локальное место. Для восстановления при остановленном сервере верните каталог целиком. Не копируйте рабочую SQLite отдельно во время записи. Схема создаётся при старте, миграции пока не предусмотрены.

## Границы этапа

База знаний (кроме приёма файлов), документы, инциденты, риски, аудиты, отчётность и редактирование настроек в браузере — явно подписанные заглушки. Нет поиска, извлечения текста, RAG, генерации документов, расчётов, реального ИИ, удаления данных, контроля версий, автоматического резервного копирования и отдельной ленты операций в интерфейсе (операции записываются в журнал). QMS-002 дорабатывает интерфейс и навигацию; QMS-003 и дальнейшие этапы не начаты.

Это однопользовательский прототип без авторизации. Слушайте только `127.0.0.1`, не публикуйте в сети. Корпоративное внедрение требует отдельного согласования ИТ и ИБ. Docker, PostgreSQL, Qdrant и тяжёлые модели не используются. Зависимости обработки документов будут добавляться на соответствующих этапах.

Проверено в Linux с Python 3.12; команды Windows подготовлены, фактическая проверка на Windows 10 ещё требуется.


## QMS-002: интерфейс и навигация

Добавлены сворачиваемое меню для узких экранов (кнопка меню, закрытие Escape), обозначение текущей страницы, ссылка перехода к содержимому для клавиатуры и возврат на главную. Кнопка светлой/тёмной темы доступна на всех разрешениях; выбор сохраняется, если браузер разрешает локальное хранилище. При запрете хранилища тема работает до перехода на другую страницу.

На страницах модулей показаны назначение и реальные ограничения. Настройки отображают текущий провайдер и лимит файла без возможности менять серверную конфигурацию. Список файлов представлен таблицей с горизонтальной прокруткой на узком экране. Чат и загрузка показывают ожидание, ошибки и блокируют повторное нажатие кнопки во время запроса. После ошибки текст чата сохраняется для повторной отправки. Для неизвестного адреса в браузере есть русская страница 404.

### Обновление существующей копии на Windows

1. Остановите сервер: Ctrl+C в PowerShell.
2. Сделайте резервную копию каталога `data`.
3. Скачайте свежий ZIP ветки main из GitHub. Из распакованного проекта перенесите в вашу рабочую папку `app`, `tests`, `README.md` и `requirements.txt` с заменой файлов. Не заменяйте свои `.env`, `.venv` и `data`.
4. Запустите прежнюю команду Uvicorn. В браузере нажмите Ctrl+F5, чтобы обновить CSS и JavaScript.

### Необязательная браузерная проверка для разработчика

Для обычной работы приложения Playwright не требуется. Для повторения UI-проверки в тестовом окружении установите `playwright==1.62.0`, выполните `python -m playwright install chromium`. Запустите сервер с отдельным каталогом синтетических данных на порту 8002, затем `python tests/browser_smoke.py`. Параметр `QMS_TEST_URL` меняет адрес сервера, `QMS_CHROMIUM_PATH` позволяет использовать установленный Chromium. Скрипт отправляет тестовый запрос и сохраняет синтетический файл; не направляйте его на рабочие данные.
