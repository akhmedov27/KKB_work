# QMS Assistant KKB

Локальное рабочее пространство менеджера системы менеджмента качества. Добавлен код этапов **QMS-001–QMS-006** и пять итераций **QMS-008 — статистика инцидентов**, с экспортом Excel и периодического отчёта Word из QMS-007 по ТЗ версии 1.0. Используйте только синтетические тестовые данные. Это прототип, а не готовая медицинская или экспертная система.

## Запуск на Windows 10

Требуется Python 3.12+ (64-bit), установленный с опцией **Add python.exe to PATH**. Откройте PowerShell в папке проекта и выполняйте команды по одной:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000** в браузере. PowerShell оставьте открытым. Остановить сервер: Ctrl+C. Если порт занят, используйте `--port 8001` и соответствующий адрес. Активировать окружение и менять ExecutionPolicy не нужно. Команды запускаются из корня проекта. Используйте один процесс сервера: один файл обрабатывается за раз.

Файл `.env` необязателен: настройки по умолчанию работают без него. При необходимости скопируйте `.env.example` в `.env`, не заменяя существующую конфигурацию. Если команда `python` не показывает номер версии, сначала исправьте установку Python или PATH; не продолжайте следующие команды.

Linux:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

При первой установке зависимостей нужен интернет. Для MockProvider, поиска и обработки файлов интернет не требуется (Groq и DeepSeek требуют интернет): JavaScript, CSS и HTMX хранятся в проекте.

## Обновление существующей копии на Windows

1. Остановите сервер: Ctrl+C.
2. Сделайте полную резервную копию папки `data` в отдельное место.
3. Скачайте свежий ZIP ветки main из GitHub. Перенесите `app`, `tests`, `README.md`, `requirements.txt` в вашу рабочую папку с заменой файлов. **Сохраните свои `data`, `.env`, `.venv`.**
4. При обновлении с QMS-003 или более раннего этапа установите зависимости QMS-004 (для перехода с QMS-004/QMS-005 на QMS-006 новых зависимостей нет):

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

5. Обновите также `.env.example`, не заменяя свой `.env`. Для Groq или DeepSeek внесите параметры из раздела QMS-006 ниже; без этого останется MockProvider.
6. Запустите прежнюю команду Uvicorn и нажмите Ctrl+F5 в браузере. Не запускайте старую и новую версии одновременно с одной базой.

Схема SQLite обновляется автоматически при старте. Перед изменением существующей базы создаётся проверенная резервная копия SQLite в `data/backups`. Если копию создать или проверить нельзя, обновление не продолжается. Повторный запуск не дублирует миграцию.

## Что работает

- Русскоязычный интерфейс, восемь разделов навигации, мобильное меню с закрытием Escape, обозначение текущего раздела и навигация с клавиатуры.
- Светлая/тёмная темы. Выбор хранится в браузере; при запрете localStorage тема действует до перехода на другую страницу.
- MockProvider по умолчанию; адаптеры Groq / DeepSeek API с явным разрешением на каждый запрос и адаптер существующего локального OpenAI-совместимого сервера. Живой ответ требует API-ключа и доступа к API выбранного сервиса; для Groq используйте доступный вашему аккаунту Free Plan в пределах его лимитов.
- Отдельные диалоги с названиями до 120 символов. Пара запрос/ответ и время активности сохраняются одной транзакцией; ошибка записи не оставляет половину пары. На странице до 50 сообщений, более ранние доступны по ссылке. Список диалогов — по 20 записей. Главная без параметров открывает последний активный диалог, URL с `conversation_id` сохраняет выбор.
- Загрузка непустых DOCX/XLSX/PDF до 10 МиБ по умолчанию. Оригиналы получают случайные внутренние имена и сохраняются локально; путь исходного имени не используется. Размер, название и дата сохраняются в SQLite. Каталог оригиналов не публикуется веб-сервером.
- Локальное извлечение и сохранение текста, просмотр результата и ошибок, повторная обработка старых документов.
- База знаний: поиск по названию, номеру и тексту, фильтры, ручная классификация и реквизиты, ссылки на источники и напоминание о пересмотре.
- Инциденты: отдельный импорт XLSX с выбором столбцов и подтверждением, проверка ошибок и повторов, статистика, сравнение периодов, диаграммы и экспорт Excel. Этот модуль не зависит от ИИ или API-ключа.
- Журнал операций и ошибок с ротацией, без текста запросов и документов, исходных имён файлов, секретов или необработанных исключений парсеров.

## QMS-004: загрузка и обработка документов

В «Базе знаний» загрузите тестовый документ. Дождитесь результата и нажмите **«Открыть документ»**. В списке можно открыть ранее загруженный файл и нажать **«Извлечь текст»**. Повторная обработка заменяет сохранённый результат для этого файла. Она не создаёт новую копию оригинала и не меняет его дату загрузки.

Поддерживается:

| Формат | Извлекается | Ограничения полноты |
| --- | --- | --- |
| DOCX | Основной текст и текст ячеек таблиц верхнего уровня, в порядке блоков | Без колонтитулов, текстовых полей, вложенных таблиц, OCR изображений, исходного оформления и определения страниц |
| XLSX | Значения ячеек с названиями листов и номерами строк | Формулы не вычисляются: видны только сохранённые в файле результаты. Макросы, диаграммы и внешние источники не запускаются |
| PDF | Доступный текстовый слой с номерами страниц | Без OCR. Порядок чтения сложных колонок и полнота текста зависят от структуры PDF |

Статусы: **«Не обработан»**, **«Текст извлечён»**, **«Нет доступного текста»**, **«Ошибка обработки»**. PDF-скан без текста не выдаётся за успешно распознанный документ. Смешанный PDF может иметь страницы без текста — об этом выводится предупреждение. Проверяйте результат по оригиналу.

Если файл повреждён, имеет неверное внутреннее содержимое, защищён паролем или превышает лимиты обработки, оригинал и его метаданные остаются в хранилище, а статус объясняет ошибку. Извлечённый текст не подставляется в чат автоматически. Явно скопированный пользователем синтетический фрагмент можно добавить в запрос ИИ отдельно. Само извлечение не является анализом; локальный поиск по результатам доступен в QMS-005.

### Ограничения ресурсов и обработка

- Один процесс разбора за раз на процесс сервера; при занятости новый файл сохраняется как «Не обработан», обработку можно повторить кнопкой.
- Разбор запускается отдельным процессом с тайм-аутом 20 секунд; по истечении времени процесс завершается. Это не полноценная изолированная песочница.
- Не более 500 000 символов текста; превышение возвращает ошибку вместо молчаливого усечения.
- Office: не более 2000 ZIP-элементов и 32 МиБ распакованных данных; также проверяется чрезмерная степень сжатия. Архивы не распаковываются на диск. XML с DTD и сущностями отвергается. Пакеты с двоичными вложениями или макросами не поддерживаются.
- XLSX: до 20 листов, 50 000 строк на лист и 100 000 просмотренных ячеек суммарно (включая пустые ячейки в диапазоне).
- PDF: до 200 страниц. Документы с паролем не поддерживаются.
- В Linux процесс разбора дополнительно ограничен 512 МиБ виртуальной памяти и 20 секундами CPU. В Windows жёсткого лимита памяти в этой реализации нет: применяются тайм-аут и ограничения объёма/обхода документа.

Парсеры не открывают документы в Word/Excel, не выполняют содержимое, формулы или макросы и не переходят по ссылкам. Антивирусная проверка не реализована. Проверка формата не гарантирует безопасность любого файла; используйте тестовые документы из известных источников.

## QMS-005: база знаний и поиск

Откройте «База знаний». Введите слово или фразу и нажмите **«Найти»**. Поиск выполняется локально по имени файла, наименованию, номеру документа и успешно извлечённому тексту. Он не вызывает ИИ, не выполняет внешних запросов и не требует отдельного сервиса или индексации.

### Как устроен поиск

- Ищется буквальное вхождение введённой фразы без учёта регистра, в том числе русского. Символы `%`, `_` и кавычки не являются шаблонами или командами.
- Нет морфологии, ранжирования, исправления опечаток и смыслового поиска. `ё` и `е` различаются; пробелы и переносы строк внутри фразы значимы. Если длинная фраза не находится в PDF, попробуйте отдельное слово.
- Фильтры статуса, типа документа и подразделения применяются совместно с запросом. Подразделение ищется по части названия без учёта регистра. Кнопка сброса возвращает полный список.
- По умолчанию видны все статусы, включая неуказанный, архивный и отменённый. Статус документа и статус обработки — разные поля. Результат поиска не подтверждает, что документ действующий.
- Результаты показываются по 20 документов, новые загрузки — первыми. Есть общее количество и переход между страницами с сохранением фильтров. Ограничения списка в 100 файлов больше нет.
- В результатах выводится первый подходящий фрагмент текста. Совпадение только в имени/номере обозначается отдельно. Ошибочные и пустые результаты извлечения не участвуют в поиске по содержимому, но файл можно найти по названию.

Поиск использует параметризованные запросы SQLite с Unicode `casefold`. Просматриваются сохранённые тексты, без загрузки всего корпуса в память приложения; в результаты передаются только короткие фрагменты. Это простой поиск для небольшого локального реестра: для большого корпуса время поиска растёт с объёмом текстов. Полнотекстовый индекс и смысловой поиск пока не реализованы.

### Карточка документа и классификация

Откройте документ по названию. В «Реквизитах документа» можно вручную сохранить:

- наименование (до 255 символов), номер, версию/редакцию;
- тип: СТУ, ОАР, положение, инструкция, регламент, процедура, документ аудита, отчёт, другое или не указан;
- статус: не указан, действующий, архивный, отменённый;
- подразделение, дату утверждения и дату пересмотра.

Пустое наименование означает отображение исходного имени файла. Даты необязательны, некорректные значения отклоняются без изменения прежних реквизитов. Дата загрузки и исходное имя сохраняются независимо от введённых реквизитов. Тип и статус не угадываются автоматически. В новой и старой карточке они по умолчанию **«Не указан»**.

У действующего документа с датой пересмотра раньше текущего локального дня появляется напоминание **«Срок пересмотра истёк»**. Оно не отменяет документ и не подтверждает несоответствие. Система пока не связывает файлы в цепочки редакций и не определяет автоматически последнюю действующую версию. Изменение реквизитов заменяет текущие значения; истории их изменений пока нет. При работе в нескольких вкладках сохраняется последнее отправленное состояние карточки.

### Ссылки на источники

Новые и повторные извлечения сохраняют координаты: основной текст DOCX, номер страницы PDF, название листа XLSX. Из результата поиска можно перейти прямо к соответствующему фрагменту на странице документа. Номера разделов DOCX и номера страниц Word не определяются и не придумываются. Номер, версия и статус документа берутся из ручных реквизитов.

Для текстов, извлечённых до QMS-005, координат нет: поиск работает и ведёт к полному тексту, но страница/лист не указываются. Нажмите **«Повторить извлечение»**, чтобы получить координаты. Они записываются парсером отдельно от текста: имитация строки «Страница 999» внутри документа не становится координатой источника.

Это выдача фрагментов и ссылок на источники, **не ответы ИИ**. В QMS-006 добавлен отдельный чат с ИИ; он не получает содержимое базы автоматически. Исходный документ остаётся основанием для проверки полноты текста и актуальности редакции.

### Самостоятельная проверка этапа

Загрузите тестовый документ, откройте карточку, заполните название, номер, тип и статус. Сохраните и обновите страницу. Найдите его по части названия, номеру и слову из текста в другом регистре. Проверьте фильтры действующих/архивных документов и ссылку источника. Повторите извлечение старого PDF/XLSX и проверьте переход к странице/листу. Перезапустите сервер: реквизиты, тексты и история чатов должны остаться.

## QMS-006: подключение ИИ (Groq / DeepSeek)

**Состояние проверки:** код адаптеров, контроль отправки, обработка ошибок и интерфейс проверены автоматическими тестами. Реальных API-ключей в среде разработки нет; живые запросы в Groq и DeepSeek не выполнялись. Это не подтверждение работоспособности вашего аккаунта, модели или доступа к API. Проверка живого ответа остаётся отдельным шагом после настройки ниже.

### Настройка Groq на вашем компьютере

1. Откройте [Groq Console — API Keys](https://console.groq.com/keys), войдите или зарегистрируйтесь, выберите **Create API Key**. Ключ сохраните только у себя. Условия Free Plan, доступность по аккаунту/региону и лимиты проверяйте в консоли Groq: приложение не гарантирует бесплатность запросов и не включает платный тариф.
2. Остановите сервер и обновите код из GitHub, сохранив свои `data`, `.env`, `.venv`. Новых зависимостей и изменения схемы базы для поддержки Groq нет. Обновлённый `.env.example` содержит пример Groq, но не заменяет ваш действующий `.env` автоматически.
3. В локальном `.env` измените или добавьте **все** параметры ниже. Не оставляйте старый адрес или ключ DeepSeek при выборе Groq:

   ```dotenv
   QMS_AI_PROVIDER=cloud
   QMS_CLOUD_SERVICE=groq
   QMS_CLOUD_ENABLED=true
   QMS_CLOUD_ENDPOINT=https://api.groq.com/openai/v1/chat/completions
   QMS_CLOUD_MODEL=llama-3.1-8b-instant
   QMS_CLOUD_API_KEY=ВАШ_API_КЛЮЧ_GROQ
   ```

4. Перезапустите сервер, нажмите Ctrl+F5. В настройках и отметке согласия должно быть написано **Groq**, а ключ отображается только как «Задан».
5. Напишите синтетический запрос «Ответь одним словом: готово», разрешите отправку в Groq и нажмите «Отправить». Это отдельная проверка вашего аккаунта, модели и сети; она не выполнялась в среде разработки. Если лимит Free Plan исчерпан, приложение покажет ошибку 429 без повторов и без переключения на другой сервис.

`llama-3.1-8b-instant` присутствует в перечне моделей официального SDK Groq на момент разработки; фактическую доступность и ограничения проверяйте в вашем аккаунте. Другую поддерживаемую текстовую модель можно задать в `QMS_CLOUD_MODEL`. Ключ сюда не присылайте, на GitHub не загружайте.

Для Groq используется официальный endpoint `/openai/v1/chat/completions` и параметр `max_completion_tokens`; дополнительный SDK не устанавливается, используется httpx. Адрес подтверждён исходниками [официального SDK Groq](https://github.com/groq/groq-python). Страница документации в console.groq.com была недоступна из среды разработки; условия бесплатного тарифа в ней не проверены.

### Настройка DeepSeek на вашем компьютере

1. Получите API-ключ в своём аккаунте [DeepSeek Platform](https://platform.deepseek.com/). Доступ к веб-чату и доступ к API — разные вещи; для API могут потребоваться отдельный баланс и оплата. Используйте доступный вашему аккаунту идентификатор модели.
2. Остановите сервер: Ctrl+C.
3. Откройте локальный `.env` в папке проекта (например, `notepad .env` в PowerShell). Если файла нет, создайте его по `.env.example`; проверьте, что имя именно `.env`, а не `.env.txt`.
4. Измените или добавьте строки, сохраняя свои прочие настройки. Вместо `ВАШ_API_КЛЮЧ` впишите ваш настоящий ключ **только на своём компьютере**:

   ```dotenv
   QMS_AI_PROVIDER=cloud
   QMS_CLOUD_SERVICE=deepseek
   QMS_CLOUD_ENABLED=true
   QMS_CLOUD_ENDPOINT=https://api.deepseek.com/chat/completions
   QMS_CLOUD_MODEL=deepseek-chat
   QMS_CLOUD_API_KEY=ВАШ_API_КЛЮЧ
   QMS_AI_TIMEOUT_SECONDS=20
   QMS_AI_MAX_TOKENS=512
   ```

5. Запустите приложение прежней командой. В «Настройках» должны отображаться провайдер `cloud`, наличие ключа без его значения и разрешение облака в конфигурации. Открытие страницы не проверяет API и не отправляет текст.
6. В чате напишите синтетический запрос, например «Ответь одним словом: готово». Отметьте разрешение отправки в DeepSeek и нажмите «Отправить». Только успешный реальный ответ проверит соединение, ключ, баланс и модель. При ошибке пришлите её текст **без ключа**, не содержимое `.env`.

Ключ не присылайте в чат, не вставляйте в поле запроса и не загружайте в GitHub. `.env` исключён из Git, `.env.example` содержит пустое поле. Приложение читает ключ из конфигурации окружения, скрывает его в интерфейсе и не записывает в журнал или SQLite. Защита локального `.env` правами доступа остаётся задачей владельца компьютера.

### Что именно отправляется

- Облако выключено по умолчанию. Для облачного сервиса нужны одновременно `QMS_AI_PROVIDER=cloud`, `QMS_CLOUD_ENABLED=true`, корректные параметры и отдельная отметка разрешения на каждый запрос. `QMS_CLOUD_SERVICE` выбирает `groq` или `deepseek`; существующие конфигурации без этого поля сохраняют выбор DeepSeek.
- В запрос передаются системная инструкция приложения, **только текущий вопрос** (до 4000 символов) и необязательный фрагмент (до 6000 символов), который пользователь сам ввёл в отдельное поле.
- История переписки, оригиналы файлов, реквизиты и тексты базы знаний автоматически не читаются и не отправляются. Чтобы обсудить тестовый фрагмент, скопируйте его вручную, при необходимости укажите источник и проверьте содержимое перед отправкой. Используйте только синтетические данные, без медицинской/персональной информации и внутренних документов.
- Каждый запрос самостоятельный: видимая история хранится локально, но модель не получает прошлые сообщения и может не понять «продолжи» без явного контекста.
- Отметка разрешения сбрасывается после каждой попытки, включая ошибочную. Сервер также проверяет разрешение; одного изменения HTML недостаточно. Запросы из браузера с посторонним Origin отклоняются.
- Groq получает запрос только на `https://api.groq.com/openai/v1/chat/completions`, DeepSeek — только на разрешённый endpoint хоста `api.deepseek.com`. Пара «выбранный сервис — адрес» проверяется до передачи ключа; несовпадение блокирует запрос. Редиректы не выполняются, проверка TLS не отключается. Модель не получает инструменты, доступ к диску, ключу или базе данных; её текст не исполняется.

При успешном ответе текущий вопрос, явно добавленный фрагмент и ответ сохраняются в локальную историю вместе с выбранным провайдером и моделью запроса. Это позволяет отличать старые тестовые ответы, Groq и DeepSeek; смена текущего сервиса не переименовывает прежние ответы. При ошибке провайдера пара сообщений не сохраняется и не заменяется ответом MockProvider. Запись в SQLite выполняется после HTTP-вызова, без удержания транзакции во время ожидания.

### Ограничения и отключение

Одновременно выполняется один запрос ИИ на процесс приложения. Автоматических повторов нет: они могли бы повторно передать данные и вызвать оплату. Обрабатываются ошибки ключа/доступа, баланса, лимита, тайм-аута, неверного формата и размера ответа. Сырые ответы об ошибках не показываются и не записываются в журнал.

Лимит результата — 20 000 символов и 256 КиБ HTTP-тела. При остановке генерации по лимиту токенов ответ явно отмечается как сокращённый. HTTP-тайм-ауты применяются к отдельным операциям, а общий контроль времени проверяется при получении данных; ответ может завершиться позже указанного числа секунд из-за ожидания последнего чтения. Если браузер потерял соединение, перед повторной отправкой обновите историю: провайдер мог уже выполнить и тарифицировать предыдущий запрос. Приложение не контролирует тарифы, лимиты Free Plan и хранение запросов на стороне провайдера.

Чтобы остановить передачу, задайте `QMS_CLOUD_ENABLED=false` и перезапустите сервер. Чтобы вернуться к прежнему тестовому чату, задайте `QMS_AI_PROVIDER=mock` и перезапустите. Не требуется удалять историю или файлы.

Ответ ИИ — проект для проверки человеком. Точность фактов, ссылок и выводов не гарантируется. Автоматическое подтверждение несоответствий, принятие медицинских решений, поиск по смыслу и RAG не реализованы. Системная инструкция просит не выдумывать требования и источники, но это не формальная гарантия поведения модели.

### Локальный режим

Предусмотрен HTTP-клиент уже работающего OpenAI-совместимого сервера на loopback этого компьютера (`QMS_AI_PROVIDER=local`, `QMS_LOCAL_ENDPOINT`, `QMS_LOCAL_MODEL`). Он не использует внешний прокси и не может обращаться к LAN/облачному хосту вместо локального. Авторизация локального сервера в этой версии не поддерживается. Никакие модели не скачиваются и не запускаются; тяжёлые локальные модели на вашем ПК не устанавливались. Адаптер проверен тестовым HTTP-сервером протокола, а не настоящей локальной моделью.

### Проверка разработчиком

Основной набор: `python -m pytest -q` через Python из `.venv`. Внешние ответы Groq и DeepSeek в тестах заменены `httpx.MockTransport`; ключи только синтетические. Дополнительно проверяется настоящий HTTP-запрос к тестовому серверу на loopback без модели.

`tests/browser_smoke.py` проверяет обычный MockProvider и прежние функции. `tests/browser_ai_smoke.py` запускается с явно заданным `QMS_TEST_URL` на тестовой копии с `QMS_AI_PROVIDER=cloud`, `QMS_CLOUD_ENABLED=false`; перехватывает `/chat` в браузере и не обращается к облачному API. `QMS_TEST_CLOUD_LABEL=Groq` переключает ожидаемую подпись UI-сценария с DeepSeek на Groq. Проверяет обязательную отметку, сброс разрешения, ручной фрагмент, сохранение ввода при ошибке и мобильную ширину. Такие тесты не подтверждают живой ответ модели.

## Инциденты: статистика реестра Excel (приоритет QMS-008)

Раздел **«Инциденты»** работает без Groq, DeepSeek и других ИИ. Все показатели считает Python/SQLite. Не загружайте реестр для статистики в «Базу знаний»: там выполняется другое действие — извлечение текста, с другими лимитами.

### Порядок работы

1. Откройте «Инциденты» → «Загрузить новый реестр XLSX». Выберите синтетический реестр (до `QMS_MAX_UPLOAD_MB`, по умолчанию 10 МиБ).
2. Выберите лист и проверьте сопоставление столбцов. Для предоставленного пользователем образца:

   | Назначение | Столбец |
   | --- | --- |
   | Номер инцидента | **B**, «Номер инцидента» |
   | Дата для периодов и динамики | **C**, «Дата инцидента» |
   | Дата регистрации | **F**, вторая колонка с таким заголовком (E содержит месяц) |
   | Отделение для статистики | **N**, «Отделение госпитализации пациента» |
   | Группа / подгруппа | P / Q |
   | Вид события / резервное наименование | R / S |
   | Важность / статус / срочные меры | L / Y / X |
   | Тип отделения / способ регистрации / корневая причина | O / H / V |

   Столбец **A «№» не используется для подсчёта**. Если основное название события пусто, применяется выбранное резервное. При другом формате XLSX поля можно сопоставить вручную; обязательны только номер и дата инцидента. Подписи повторяющихся заголовков различаются буквами столбцов.
3. Нажмите «Проверить данные». Предпросмотр показывает количество строк, ошибок, уникальных номеров, повторных вхождений и конфликтующих номеров, диапазон дат и применение резервного названия. Пока импорт не подтверждён, в статистике этих данных нет.
4. Скачайте при необходимости полный отчёт проверки. Выберите основу подсчёта:
   - **Один инцидент на уникальный номер** — основной вариант для вашего образца. Повтор одного номера объединяется только при одинаковых выбранных данных. Если выбранные данные различаются, подтверждение в таком режиме блокируется.
   - **Все корректные строки отдельно** — явный альтернативный режим; показатели называются «Записи», а число уникальных номеров показывается отдельно. В этом режиме повторы строк могут увеличивать частоты событий.
5. Если есть ошибки, исправьте исходник или явно отметьте разрешение импортировать только корректные строки. Строки с ошибками остаются в проверке и не попадают в расчёты. Ничего не исключается молча.
6. Подтвердите импорт. Выберите даты и категории, нажмите «Рассчитать». Скачайте «Статистику XLSX» для текущей выборки.

### Что считается

- Количество в текущей выборке и отдельное число уникальных номеров.
- Распределения по отделениям, типам отделений, группам, подгруппам, видам событий, исходным кодам важности, статусам, срочным мерам, способам регистрации и корневым причинам. В интерфейсе показаны основные таблицы, первые 10 категорий; полные таблицы есть в экспорте.
- Доля категории = количество записей категории / количество в текущей выборке × 100%. Пустые значения включаются как «Не указано». Округление до двух знаков может давать сумму долей немного выше/ниже 100%.
- Динамика по месяцу **даты инцидента**. Год из имени файла не используется. Для диапазона до 10 лет добавляются месяцы без записей; в более длинных диапазонах отображаются только месяцы с данными. Ноль не означает доказанное отсутствие инцидентов или полноту периода.
- Сравнение двух периодов одного набора при одинаковых фильтрах категорий. Изменение = количество текущего периода − количество второго; относительное изменение делится на количество второго периода. При базе 0 процент не определяется. Пересечение периодов обозначается. При разной продолжительности сравниваются количества без нормирования по дням.
- Повторяющиеся сочетания: одинаковые отделение и вид события с количеством не меньше выбранного порога (по умолчанию 2) в текущей выборке. Это не вывод о повторном событии у одного пациента, причине или установленном несоответствии.

По умолчанию включены **все статусы**, в том числе «Отменено» и «Удалено». Они не трактуются как закрытые/открытые автоматически. Коды важности A–I сохраняются без придуманной клинической расшифровки. Можно выбрать несколько отделений (запись должна относиться к любому из выбранных), исключить несколько статусов и задать одно значение группы, подгруппы, вида события, важности, статуса и точный номер инцидента. Все остальные ограничения применяются одновременно. Если выбранный статус одновременно исключён, выборка будет пустой. Начало и конец периода включаются в выборку. `__empty__` в фильтре выбирает отсутствующее значение. Подсказки категорий содержат до 500 значений. Поиск отделений проверяет весь выбранный набор и показывает до 30 совпадений; выберите полное название из подсказки. Реестр показывается по 50 записей, экспорт включает всю отфильтрованную выборку.

### Поиск отделений и расширенная аналитика

Полные названия остаются на сайте, в реестре и Excel. В поле поиска отделения можно ввести `ГХО`, `ОАР 2`, `НХО 1`, `ТО 1` или `НРС`, затем выбрать предложенное полное название мышью или клавишами стрелок и Enter. Добавьте несколько отделений; крестик убирает выбранное. Очистите незавершённый поисковый ввод перед расчётом.

Справочник `app/reference/department_aliases.json` содержит согласованные сокращения; `ХО НРС/ЭКС` и `НРС` ведут к одному полному названию. Используются `ТО 1`, `ТО 2`, `ТО 3`; добавлено `ОАР 1`. Будущие отделения без записей явно обозначены и дают нулевую выборку. Сокращение «ЭНДОКР» отсутствует, само отделение не удалено. Справочник помогает искать и не переписывает импортированные значения, не объединяет разные исходные названия. Редактора справочника в браузере пока нет.

Дополнительные инструменты:

- Исключение статусов: отметьте, например, «Отменено» и «Удалено». По умолчанию исключений нет.
- Квартальная динамика по дате инцидента; неполный период показывает только попавшую в фильтры часть квартала.
- Парето по группе, виду события или корневой причине. В «Настройках Парето и повторяемости» выберите поле и порог накопленной доли (по умолчанию 80%). Категория, пересекающая порог, включается. Пустые значения участвуют как «Не указано»; это частоты записей, а не доказательство причин или клинической тяжести.
- Сравнение отделений и групп между двумя выбранными периодами при одинаковых фильтрах. Процент изменения при базе 0 не определяется. Количества не нормируются по продолжительности периода.
- Таблица «Отделения и группы событий»: количество, доля внутри отделения и доля всей выборки. Показаны только сочетания с записями.
- Настраиваемый минимум повторяемости влияет только на таблицу повторяющихся сочетаний, а не на общее количество.
- Счётчики незаполненного отделения и корневой причины проверяют пустоту поля, без оценки правильности значений.

Диаграмма Парето показывает первые 15 категорий, новые таблицы — первые 20; полные таблицы входят в XLSX. Длинную причину можно раскрыть через «Полный текст категории». Фильтры сохраняются при переходе по страницам и экспорте. Новые листы: «Кварталы», «Парето», «Сравнение отделений», «Сравнение групп», «Отделения и группы»; листы сравнения появляются при заданном втором периоде.

Для обновления остановите сервер, сохраните резервную копию `data`, замените код приложения и запустите прежней командой. Новых зависимостей и изменений схемы относительно первой итерации инцидентов нет; повторный импорт Excel не требуется. Сохраните свои `.env`, `data` и `.venv`. Для статистики API-ключ не нужен.

### Графики и сохранение PNG

В разделе «Инциденты» откройте блок **«Графики инцидентов»** и выберите рисунок в списке:

- Динамика по месяцам — последние 24 месяца текущего диапазона.
- Горизонтальные столбцы по отделениям — первые 15 по количеству, с полными названиями.
- Тепловая карта «Отделение × месяц» — первые 15 отделений и последние 24 месяца.
- Тепловая карта «Отделение × группа событий» — первые 15 отделений и первые 12 групп.
- Статусы по отделениям — состав первых 15 отделений в количестве или процентах внутри каждого отделения. Первые 8 статусов показаны отдельно, остальные включены в «Другие статусы», без потери их количества.
- Сравнение отделений за два периода — парные столбцы, первые 15 по абсолютному изменению. Сначала задайте обе даты второго периода в фильтрах и нажмите «Рассчитать».
- Заполненность данных — наличие отделения, вида события и корневой причины в количестве или процентах. Это проверка пустоты, не правильности сведений.
- Парето — первые 15 категорий с накопленной долей от всей выборки и выбранным порогом.

На странице сравнения двух выгрузок дополнительно доступна диаграмма четырёх групп номеров: новые, отсутствующие, изменённые и без изменений.

Графики учитывают действующие фильтры и основу подсчёта набора. Полные названия отделений переносятся на строки. Для очень длинных категорий Парето рисунок показывает начало названия, полный текст есть в раскрываемой таблице «Данные выбранного графика». У тепловых карт номера столбцов расшифрованы под рисунком. Ноль означает отсутствие записей в выбранном наборе, а не доказательство полноты периода.

При наведении показываются точные значения. Нажатие на столбец или ячейку со ссылкой применяет соответствующие ограничения и открывает исходные записи; даты ячейки месяца пересекаются с текущим диапазоном, остальные фильтры сохраняются. Для второго столбца сравнения используется второй период. В диаграмме выгрузок нажатие открывает соответствующую категорию номеров. Перехода нет у заполненной части показателя качества и у объединённых «Других статусов», поскольку это не одно значение фильтра. Элементы со ссылками доступны через Tab и Enter. Добавлен отдельный фильтр корневой причины; `__empty__` выбирает незаполненное поле.

Кнопка **«Сохранить PNG»** сохраняет рисунок через загрузки браузера. В PNG включены название, номер набора, текущие даты, количество выборки и пояснения; полный список фильтров хранится в сводке XLSX, поэтому для воспроизводимого отчёта сохраняйте также Excel. Фон PNG белый и подходит для вставки в Word, в том числе при тёмной теме сайта. Размер картинки ограничен примерно 16 млн пикселей, длинные графики уменьшаются при сохранении. Цвета категорий относятся к текущему рисунку, не к закреплённому справочнику статусов.

Рисунки строятся локально на SVG и Canvas, без CDN, сетевых запросов, ИИ и новых зависимостей. На узком экране прокручивается область графика; полные таблицы доступны ниже и в Excel. Верхние пределы относятся только к рисункам, данные набора не обрезаются. Для подробного просмотра отфильтруйте нужные отделения или даты. Интерактивные рисунки и PNG не добавляются автоматически в XLSX; существующие таблицы и Excel-диаграммы сохраняются.

### Отчёт за месяц или квартал (Word и Excel)

1. В статистике инцидентов задайте нужные отделения, исключения статусов и другие категории, нажмите «Рассчитать».
2. Нажмите **«Отчёт за месяц или квартал»**. Также есть ссылка в меню «Отчётность» — она использует последний подтверждённый набор без ограничений категорий.
3. Выберите вид периода, год и месяц либо квартал, затем нажмите **«Сформировать предпросмотр»**. Для месячного отчёта поле квартала не используется, для квартального — поле месяца. При первом открытии предложен текущий месяц; выберите нужный период явно.
4. Проверьте количество, предыдущий период, источник и фильтры. Отчёт всегда использует полный календарный месяц/квартал по дате инцидента и автоматически предыдущий календарный месяц/квартал **того же набора**. Исходные даты и даты сравнения панели статистики заменяются этим выбором, категории сохраняются. Длительности периодов показаны отдельно; количества не нормируются по дням.
5. При необходимости введите комментарий до 12 000 символов и нажмите **«Скачать отчёт DOCX»**. Для полных таблиц используйте **«Скачать полную статистику XLSX за этот период»**.

DOCX содержит источник, период, основу подсчёта, все применённые фильтры, основные показатели и изменение относительно предыдущего периода, диаграммы месячной динамики и отделений, ведущие категории, Парето, повторяемость, сравнение отделений/групп, заполненность данных и комментарий. В таблицах категорий показаны первые 10; первые 10 сравнений отсортированы по абсолютному изменению. Полные распределения и реестр — в XLSX. Строки таблиц переносятся целиком, заголовки повторяются на следующих страницах.

Текст, подписи и таблицы можно редактировать в Word. Полосы диаграмм вставлены как небольшие встроенные PNG с общей шкалой для каждой диаграммы, без внешних ссылок. При ручном изменении чисел в Word полосы автоматически не пересчитываются — сформируйте отчёт повторно. Утверждённый шаблон ККБ пока не применён; документ явно обозначен как рабочий отчёт.

Комментарий передаётся только локальному серверу при скачивании DOCX, не отправляется ИИ и не сохраняется в базе или журнале. Он остаётся в поле после скачивания, но сбрасывается при обновлении страницы или расчёте другого периода. Автосохранения черновика и архива созданных отчётов нет; сохраняйте скачанные файлы самостоятельно. Никаких медицинских выводов или выводов ИИ не создаётся. При базе сравнения 0 процент не определяется; пустая выборка даёт явное сообщение. Даты всего набора не подтверждают полноту календарного периода.

Для обновления достаточно заменить код `app`, сохранив `.env`, `data`, `.venv`, перезапустить сервер и нажать Ctrl+F5. Новых зависимостей нет: python-docx уже используется для чтения документов. Схема SQLite остаётся v5, повторный импорт не требуется. LibreOffice, Word, графический сервер или шрифтовые пакеты на сервере для создания DOCX не нужны. Открыть файл можно в Word или другом совместимом редакторе. В тёмной теме календарь и поля дат используют системную тёмную палитру браузера, в светлой — светлую.

### Сравнение двух выгрузок

В разделе «Инциденты» нажмите **«Сравнить две выгрузки»**. Нужны два подтверждённых импорта. Выберите исходный и новый наборы и нажмите «Сравнить выгрузки». Порядок выбирается явно, без предположений по имени файла или времени загрузки. Повторная загрузка полностью идентичного файла возвращает прежний набор; для сравнения нужны разные наборы.

Сравнение использует точный **номер инцидента (B в вашем образце)**. Порядковый A и номера строк не участвуют в сопоставлении; строки обоих исходников показаны для проверки. Номера сравниваются как сохранённые строки: `001` и `1` различаются. Нельзя сравнить набор с самим собой, неподтверждённый импорт или набор с несколькими записями одного номера. Последний нужно импортировать по уникальным номерам с устранением конфликтов.

Результат разделён на четыре группы: только в новом наборе, отсутствующие в новом наборе, изменённые, без изменений. Для изменённых номеров раскрываются поля «Было / Стало», включая дату, статус, отделение, вид события и причину, если эти поля выбраны в обоих импортах. Сравниваются сохранённые значения точно, включая регистр. Резервное наименование учитывается как итоговый вид события. Словарь сокращений не переписывает значения при сравнении. Поля, не выбранные хотя бы в одном импорте, явно исключаются из сравнения, а не считаются очищенными.

«Отсутствует» не означает удаление или закрытие инцидента. Панель показывает границы дат и предупреждает при разных диапазонах или сопоставлениях столбцов. Совпадение границ дат не доказывает полноту. «Без изменений» относится только к перечисленным аналитическим полям; исходные XLSX целиком и исключённые идентифицирующие столбцы не сравниваются.

Фильтры панели статистики здесь не применяются: сравниваются два полных набора. Показаны количество по четырём группам, частоты изменений отдельных полей и распределения статусов, отделений и групп до/после. Один номер с несколькими изменениями учитывается в нескольких строках сводки полей. Изменение распределений включает новые и отсутствующие номера, поэтому оно не равно числу номеров с изменённым полем.

Списки номеров показываются по 50 на странице; распределения — первые 20 по названию. **«Скачать сравнение XLSX»** выгружает все категории, все изменения полей, строки обоих исходников и полные распределения. Исходные наборы не изменяются, не объединяются и не удаляются. Сравнение выполняется заново по запросу; отдельная история запусков сравнения пока не хранится. API-ключ, новые зависимости и миграция схемы не нужны.

### Сохранность и воспроизводимость

Каждый подтверждённый импорт — отдельный набор. По умолчанию открывается последний подтверждённый; предыдущие доступны через «Последние импорты». Наборы не складываются автоматически: повторные выгрузки могут перекрываться. Их можно сопоставить через «Сравнить две выгрузки» без объединения записей. Повторное подтверждение одного импорта не добавляет записи, в том числе при параллельных запросах. Повторная загрузка **идентичных байтов файла** с тем же листом и сопоставлением возвращает ту же проверку. Пересохранённый Excel может иметь другой SHA-256 и станет отдельным набором.

Оригинал сохраняется в `data/incident_imports/`, выбранные аналитические поля, ошибки и номера исходных строк — в SQLite. В расчётах используется только подтверждённый набор. ФИО, номера историй болезни, имена врачей и ответственных, описания и комментарии не импортируются в аналитические записи; оригинальный файл всё равно содержит исходные столбцы и хранится локально. Перед загрузкой используйте только синтетические примеры. Логи содержат идентификаторы и количества, без содержимого ячеек. Код модуля не вызывает ИИ.

Схема обновляется до v5 транзакционно с резервной копией SQLite; прежняя история чатов, документы и реквизиты сохраняются. Полную копию `data` нужно делать отдельно, она включает оригиналы. Удаление, редактирование подтверждённых записей, замена набора и смена его основы подсчёта пока не предусмотрены.

### Проверка XLSX и ограничения

- До 20 листов, заголовок в первых 10 строках, до 20 000 строк данных, 100 столбцов и 1 000 000 просмотренных ячеек. Выбранные текстовые значения — суммарно до 10 млн символов; вид события и корневая причина до 5000 символов, прочие категории до 500. Текст не обрезается: превышение отмечается ошибкой.
- Номера сохраняются как идентификаторы (текст или целое число). Даты принимаются как типизированные даты Excel, ДД.ММ.ГГГГ или ГГГГ-ММ-ДД; числовые значения без формата даты не угадываются как даты.
- Пробелы и неразрывные пробелы нормализуются. Пустые значения и текстовые NULL/None/NaN считаются неуказанными. При группировке регистр названия не учитывается. Сокращения, опечатки и разные названия организаций/отделений не объединяются без явных правил; справочник пользовательских соответствий пока не реализован.
- Формулы в выбранных полях не выполняются и приводят к ошибке строки. Макросы и активные двоичные вложения не поддерживаются. XML с DTD/сущностями отклоняется. Служебные `xl/printerSettings/printerSettings*.bin` разрешены только для импорта инцидентов и игнорируются; это настройки печати, они не исполняются. Прочие ограничения Office-архивов (32 МиБ распакованных данных и 2000 элементов) сохраняются.
- Чтение выполняется отдельным процессом, один файл за раз, с тайм-аутом 30 секунд; в Linux дополнительно 512 МиБ виртуальной памяти / 25 секунд CPU. В Windows жёсткий лимит памяти не реализован, но лимиты данных и тайм-аут действуют.
- Строки экспорта записываются в XLSX именно как текст, чтобы значения, начинающиеся с `=`, не становились формулами. Экспорт содержит сводку, динамику, категории, повторяемость, реестр и отчёты проверки; диаграммы отделений и динамики создаются средствами openpyxl. Не включаются именные и медицинские идентифицирующие поля исходника.

### Проверка на предоставленном синтетическом образце

В среде разработки проверены все 6636 строк: **6450 уникальных номеров B**, **186 повторных вхождений**, без конфликтов выбранных полей и ошибок. Пять уникальных номеров имеют даты 2025 года. За период 01.01.2026–31.12.2026 — **6445** уникальных номеров. В 822 строках использовано резервное название из S. Числа независимо сверены с исходным XLSX, выгрузкой реестра, суммами динамики и отделений. В браузере выполнен полный цикл на этом файле. Это проверка синтетического образца, а не медицинский вывод.

Автотесты модуля: `python -m pytest tests/test_incidents.py -q` через `.venv`. Необязательный UI-сценарий: `tests/browser_incidents_smoke.py` с `QMS_TEST_URL` отдельного тестового сервера и `QMS_INCIDENT_XLSX` пути синтетического файла, `QMS_EXPECT_UNIQUE` для ожидаемого количества. Он **подтверждает импорт и скачивает отчёт**, поэтому не запускайте его на рабочем наборе. Пользовательский файл не включён в GitHub.

### Что пока не реализовано в аналитике

Нет автоматической интерпретации ИИ, произвольных конструкторов показателей, редактора справочника отделений и межнаборного объединения. Частоты на 1000 госпитализаций/процедур не рассчитываются без соответствующих знаменателей. Сроки устранения и доли «закрытых» не вычисляются без согласованных правил статусов и нужных дат. Эти определения не подменяются предположениями.

В Git не включаются `.env`, `.venv`, `data`, логи и кеши.

### Совместимость и миграции

Схема версии 0 (QMS-001/QMS-002) обновляется с переносом сообщений в «История до QMS-003», с сохранением идентификаторов, ролей, текста, дат и метаданных документов. Схема версии 1 (QMS-003) обновляется добавлением таблицы результатов извлечения. Схема версии 2 (QMS-004) получает таблицу ручных реквизитов и поле координат источников для извлечённого текста. Схема версии 3 (QMS-005) получает поля провайдера и модели сообщения; старые сообщения помечаются `mock`. Схема версии 4 получает отдельные таблицы загрузок, проверок, строк предпросмотра и подтверждённых записей инцидентов. Текущая версия — **`PRAGMA user_version=5`**. Перед миграцией создаётся `data/backups/qms-before-v5-<дата>-<идентификатор>.sqlite3`. Старые резервные копии не удаляются. Миграция транзакционная; ошибка откатывает изменения схемы. Более новая или неизвестная старая схема останавливает запуск.

Старые оригиналы автоматически не обрабатываются: откройте документ и нажмите кнопку извлечения. Старые успешно извлечённые тексты доступны для поиска сразу; координаты страницы/листа появятся после повторной обработки. Статус и тип старых документов по умолчанию «Не указан». Переписка, названия диалогов и оригинальные файлы не изменяются. После обновления базы не запускайте с ней старую версию приложения.

### Резервное копирование

Остановите сервер и скопируйте **весь каталог `data`** в защищённое локальное место. Для восстановления при остановленном сервере верните каталог целиком. Не копируйте рабочую SQLite отдельно во время записи.

Автоматическая копия перед миграцией включает только SQLite, **без оригиналов файлов**; она не заменяет полную резервную копию. Периодическое резервное копирование не реализовано. Для возврата к старой версии используйте старую полную копию `data` и соответствующую версию кода; записи, сделанные после копии, в ней отсутствуют.

## Границы этапа

По запросу пользователя приоритет отдан QMS-008, экспорту Excel и рабочему периодическому отчёту DOCX из QMS-007. Полная генерация Word/Excel QMS-007, QMS-009 и последующие этапы не начаты. Код QMS-006 проверен на тестовых HTTP-ответах; реальные Groq и DeepSeek без ключей не проверялись. Пока нет смыслового поиска, RAG, автоматической классификации, генерации произвольных Word/Excel-документов и выводов ИИ по инцидентам, расчёта рисков, аудитов и других видов отчётности. Нет автоматического доступа ИИ к базе знаний, удаления/переименования диалогов, экспорта истории, контроля версий документов и редактирования серверных настроек в браузере. Нереализованные модули обозначены как заглушки; «Отчётность» содержит переход к отчёту по инцидентам. Лента операций в интерфейсе не реализована; операции записываются в журнал.

Это однопользовательский прототип без авторизации. Слушайте только `127.0.0.1`, не публикуйте в сети. Корпоративное внедрение требует согласования ИТ и ИБ. Docker, PostgreSQL, Qdrant и тяжёлые модели не используются. Работа QMS-001–QMS-005 на Windows подтверждена пользователем. Код QMS-006 проверен в Linux; непосредственная проверка облачного API на Windows с вашим ключом ещё требуется. Новый модуль инцидентов проверен в Linux; проверка на Windows остаётся за пользователем.
